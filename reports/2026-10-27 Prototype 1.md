# 2026-10-27 Prototype 1

First end-to-end test of the Streamlit prototype (`prototype/`) with Test_6 weights on live Earth Engine data, the Datalab setup it needed, and research on how to improve the results. Method: `reports/Notebook method and pipeline.md`. Training results: `reports/Test run 6 results.md`.

## 1. What was built

| File | Content |
|---|---|
| `prototype/app.py` | Streamlit interface: model choice, location and start month, 5 result tabs (monthly maps, class shares, change in pp, sanity check, radar input), PNG/CSV downloads |
| `prototype/pipeline.py` | model loading, variant detection from the first layer's channel count, the notebook's feature computation, sliding-window inference (256 px, overlapping softmax summed), percentages, changes, annual mode |
| `prototype/gee.py` | Earth Engine: UTM grid, monthly Sentinel-1 composites with the training-data processing, terrain, Esri reference, chunked `computePixels` download |
| `prototype/model.py` | U-Net / ResNet-34, identical to the notebook |
| `prototype/launch.py` | starts the app on a remote machine; JupyterHub proxy link or a Cloudflare quick tunnel protected by a random access key |
| `prototype/README.md`, `requirements.txt`, `.streamlit/config.toml` | setup, use, limitations; upload limit 500 MB |

- Weights: upload a `<variant>_best.pt` plus that run's `model_card.json`, or pick a run folder in `Weights/` on the server (on Datalab: `Test_2`, `Test_4`, `Test_5_Full`, `Test_6`).
- The Earth Engine project ID is never sent to the browser: a blank field uses `EE_PROJECT` or `.env` on the server.
- The independent reference is the Esri 10 m Annual LULC map (`projects/sat-io/open-datasets/landcover/ESRI_Global-LULC_10m_TS`). The collection ID worked in the test.

## 2. Datalab setup: problems and fixes

| Problem | Cause | Fix |
|---|---|---|
| `uv pip install` "Permission denied", broken `.venv` symlink | root `.venv` from an earlier image; `sudo` made files root-owned | `uv venv` inside `prototype/`; never use `sudo` with `uv` |
| `sudo uv add gcloud` | installs an old unrelated PyPI library, not the gcloud CLI; it also edited the tracked `pyproject.toml` / `uv.lock` and rebuilt the root `.venv` as root | revert with `git checkout -- pyproject.toml uv.lock`, `chown` the venv back |
| `earthengine authenticate`: "gcloud command not found" | the default mode needs the gcloud CLI | `earthengine authenticate --auth_mode=notebook` |
| "Project has an incompatible OAuth2 Client configuration" | the project chosen on the login page cannot host the notebook login client | pick another project on that page; the login project and the Earth Engine project are independent |
| Credentials saved, but "Please authorize access" | "Use read-only scopes" was ticked: the token has fewer scopes than the CLI stores in the file, so every refresh fails with `invalid_scope` | log in again without read-only scopes |
| "Earth Engine API has not been used in project ..." | the Datalab-provided project has no Earth Engine API / registration, and registration failed (no owner rights) | use the user's own project that is already registered for Earth Engine, via `EE_PROJECT` |

Checks used: a refresh test of `~/.config/earthengine/credentials` (prints field names and the error only), then `ee.Initialize(project=...)` plus `ee.Number(1).getInfo()`.

## 3. Test results (Test_6 `three_month_stats_best.pt`, 2021, Jan start, 5.12 km, 25 % overlap)

The app ran through the Cloudflare tunnel on the Datalab GPU (CUDA). Both runs finished in about 30 s including the Earth Engine download.

### 3.1 Central Berlin (52.52, 13.405)

| Class | model (annual mode) % | Esri % | Esri pixels found by the model % |
|---|---|---|---|
| Built-up | 93.9 | 97.1 | 96.4 |
| Trees | 5.2 | 2.1 | 99.4 |
| Shrub & grass | 0.4 | 0.3 | 69.5 |
| Water | 0.5 | 0.5 | 59.5 |

- Pixel agreement **96.2 %**, but a map that says "built-up" everywhere would score 97.1 %. This test says little about accuracy.
- Visually correct: the Tiergarten edge and Volkspark Friedrichshain as trees; the Spree and Humboldthafen as water.
- The 12 monthly maps are almost identical, as expected for a city centre.
- Water recall is low (59.5 %) because the Spree is only a few pixels wide; sliding-window smoothing erodes thin features.

### 3.2 Potsdam (52.42, 13.03): city edge with lakes, forest and fields

| Class | model (annual mode) % | Esri % | Esri pixels found by the model % |
|---|---|---|---|
| Built-up | 32.6 | 48.0 | 67.3 |
| Cropland | 17.4 | 21.7 | 76.9 |
| Trees | 39.4 | 22.8 | 99.1 |
| Shrub & grass | 5.9 | 2.7 | 69.3 |
| Water | 4.7 | 4.8 | 92.9 |

- Pixel agreement **77.9 %**. The two maps have very similar shapes: the Havel lakes, the field blocks and the forest edges line up.
- Main disagreement: **suburbs with many trees are Trees in our map and Built-up in Esri's.** The model has 16.6 pp more Trees and 15.4 pp less Built-up.
- This is largely a **class-definition difference**, not only a model error:
  - Esri counts vegetation mixed with buildings as built area ("Low Density Built": impervious surfaces mixed with vegetation that cannot be separated at 10 m) ([Esri listing](https://www.esri.com/en-us/arcgis-marketplace/listing/products/43c1d2612d134cc19b7f95deef5469db)). In Paris, Esri labels street trees and parks as urban, WorldCover as trees ([ArcGIS blog](https://www.esri.com/arcgis-blog/?p=1509732)).
  - Our training labels are the WorldCover ∧ Dynamic World consensus. WorldCover's built-up class excludes urban green ([WorldCover docs](https://docs.terrabyte.lrz.de/datasets/esaworldcover/)). The model therefore learned the WorldCover-style answer.
  - The radar adds to it: tree crowns hide the double-bounce signal of the houses below.

### 3.3 Interpretation for the report

- Global comparisons put the three 10 m products at 65-75 % overall accuracy against ground truth, with close agreement on built area and trees ([Venter et al. 2022, Remote Sensing 14(16) 4101](https://www.mdpi.com/2072-4292/14/16/4101/html)). Agreement between two maps is therefore capped well below 100 %. 78 % agreement of a radar-only model with Esri in a mixed landscape is in that range.
- Report agreement **per class and against the majority-class baseline**. Overall agreement in a city centre is not informative.
- Choose mixed areas (city edge, agriculture, forest, water) for the sanity check and the screen recording.

## 4. How to improve (research)

Ordered by effort. Steps 1-4 change only the prototype; steps 5-7 need retraining.

1. **Fairer sanity check** (prototype, small).
   - Show the majority-class baseline next to the agreement, plus per-class F1 / IoU and Cohen's kappa.
   - Add a "harmonised" agreement where Trees inside Esri Built-up counts as definitional (or merge Built-up + Trees into one class for that number). It separates definition differences from real errors.
   - Optionally show the confusion matrix (model rows, Esri columns).
2. **Temporal smoothing of the monthly maps** (prototype, small).
   - Raw per-month classifications overstate change; Hidden Markov Models are the standard fix for land cover time series ([Lamarche et al., HMMs for annual land cover](https://research.dial.uclouvain.be/handle/2078.5/240783); [Gong et al. 2017, ISPRS IJGI 6(10) 292](https://www.mdpi.com/2220-9964/6/10/292)). A spatio-temporal window filter is the simpler baseline ([Zhu et al. 2024, Sustainability 16(18) 8127](https://www.mdpi.com/2071-1050/16/18/8127)).
   - Simplest version: average the softmax of month t-1, t, t+1 before the argmax, or a 3-month majority vote. Expected effect: less spurious month-to-month change in the change tab; real changes that last ≥ 2 months stay.
   - Show raw and smoothed change side by side, so the report can quantify the noise.
3. **Test-time augmentation** (prototype, small).
   - Predict each window also flipped horizontally / vertically and average the softmax. The training already used flips and rotations, so the model is consistent under them.
   - Flip TTA usually adds about 1-2 points mIoU in other segmentation domains ([GOOSE 2026 report](https://arxiv.org/pdf/2606.23113); [LiDAR study](https://arxiv.org/pdf/2405.14870)). No published remote-sensing ablation with numbers was found. Measure it on the test sites before claiming a gain.
   - Cost: 2-4 × inference time (Datalab: about 30 s → 1-2 min).
4. **Confidence map** (prototype, small): show the max softmax per pixel and optionally grey out pixels below a threshold. Shows where the radar is ambiguous (suburbs, wet soil, sand).
5. **Thin features (rivers, roads)** (training).
   - Water recall in Berlin was 59.5 %. Use 50 % window overlap in the app first (no retraining).
   - In training, a boundary-aware loss term or keeping the full-resolution skip (the stem output) richer would help. Low priority.
6. **Urban vs trees from radar** (training, larger).
   - Interferometric coherence separates stable buildings from vegetation, whose coherence is low ([Chini et al., IGARSS 2018](https://www.list.lu/en/environment/scientific-publications/scientific-publications-detail/polarimetric-and-multitemporal-information-extracted-from-sentinel-1-sar-data-to-map-buildings); [DLR study](https://elib.dlr.de/142813)). Earth Engine only has GRD (no phase), so coherence would need SLC processing outside Earth Engine. Out of scope before the deadline.
   - Feasible alternative inside Earth Engine: texture of VV / VH (local variance or GLCM over 3 × 3 to 7 × 7 px) as extra yearly channels. Buildings give bright, very variable point scatterers; tree crowns are smoother. Needs retraining and a new ablation.
   - Polarimetric decompositions that explain rotated buildings scattering like vegetation need full-pol data ([Thirion-Lefevre et al. 2020](https://www.mdpi.com/2072-4292/12/10/1632)); Sentinel-1 is dual-pol, so this does not apply.
7. **More city-edge training sites** (data). The training set has 134 sites; suburbs where WorldCover and Dynamic World disagree are unlabelled under the consensus rule, so the model sees few labelled mixed built/tree pixels. Adding peri-urban sites would help the class that disagrees most with Esri.

### Recommendation before the deadline

- Do 1, 2 and 3 in the prototype (small, no retraining, directly improve what the brief asks for: monthly maps and change in pp).
- Run the sanity check on 5-6 mixed sites across biomes and put the per-class table in the report, with the definition difference explained (section 3.2).
- Keep 5-7 as "future work" in the report.
